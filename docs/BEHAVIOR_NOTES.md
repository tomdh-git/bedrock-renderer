# Behaviour notes without RVAs (checklist M4b)

What each structural render function DOES, so it can be re-found after a patch by behaviour (strings, constants, call shapes) instead of by address. Details and evidence are in `docs/functions/<rva>.md` (1.26.62.01 names in brackets). Tags: [V] read in the disassembly, [I] inferred, [?] open. The anchors listed are the things to search for in a new exe; `tools/sigs/audit.py` shows which of them still match.

## bgfx core (render-prep thread)

- **Encoder submit** [bc60740]: records one draw into the current Frame. Takes the encoder, a view id, a program handle (0xFFFF means 0), an occlusion-query handle (0xFFFF = none), a depth and a keep-state byte. Rejects the draw if the encoder's discard byte is set or if no draw data was set. Allocates the draw slot with an atomic compare-exchange on the Frame's item counter (cap 0xFFFE), builds a 64-bit sort key (view id in the top 10 bits, then a mode tag 0x10 / 0x14 / 0x18 chosen by the view's sort mode, then depth or sequence), stores the key, an identity sorted index, a 0x80-byte header copied from the encoder and the 0x518-byte bind block into the 0x540-byte RenderDraw array, then resets the encoder to its default state. Anchors: MurmurHash2 constant 0x5bd1e995 (x7), default state constant 0x010000500000001F, the item-count atomic, `imul 0x540`. [V]
- **Encoder reset** [bc60d10]: restores the default draw state (0x010000500000001F), zero transform, scissor/stencil defaults and invalid handles (0xFFFF / 0xFFFFFFFF), clears the bind block. [V 6cr]
- **Frame sort** [bc61e20]: sorts the draw keys into the sorted index list with a radix sort; only reads the keys, the item count and writes the index list. Anchors: it touches exactly the three Frame offsets for keys, sorted list and item count. [V]
- **Context init tail** [bc63690]: starts the renderer thread (named "bgfx - renderer backend thread", unless single-thread mode), stamps the thread-identity magic 0x78666762 ("bgfx"), and initialises 256 per-view structs (identity matrices, invalid framebuffer handle 0xFFFF) plus two 0x2000-byte 0xFF handle tables. [V]
- **Context frame(capture)** [bc65800]: the API-side frame call. Writes a "present" record into every active surface's tail block, stamps a timestamp, takes the context lock, calls the swap function, waits on the "frame consumed" semaphore once per other surface, copies per-surface timing to a table and resets the active list. [V]
- **Swap** [bc66de0]: copies the API-side view remap (0x200 bytes), the 256 view structs (0x14000 bytes) and the per-view flags (0x100) into the submit Frame, drains the queues of destroyed handles into the handle allocators, bumps the frame number. Anchor: the string "Disabling dynamic texture handles is not supported." [V]
- **Shutdown sequence** [bc660a0]: writes a begin-shutdown command byte (1) and destroy commands into the Frame command buffers and calls frame() five times, three times in a row at the end, then writes the surface present record. [V structure, I names]
- **renderFrame** [bc63150]: render-thread step. Handles device reset/resize notifications on the renderer object, waits (with a timeout) on the "frame ready" semaphore, runs the prep step, executes the pre-command buffer, calls the renderer's submit virtual, executes the post-command buffer, posts the "frame consumed" semaphore, returns a RenderFrame code (3 = exiting). [V]
- **Render thread proc** [bc65720]: loops renderFrame(5000) until it returns exiting, recording the wait time in each Frame. [V]
- **Command interpreter** [bc68e40]: reads a byte stream with 1/2/4/8-byte aligned fields, dispatches the command byte (40-way jump table, index = byte - 1) and calls one virtual of the renderer object per command (create/destroy/update vertex layout, buffers, shaders, programs, textures, framebuffers, uniforms). Anchor: string "MemoryReader: read truncated.", the texture chunk magic 0x00584554. [V]

## D3D12 backend (render thread)

- **Submit (renderer slot 50)** [e82e230]: consumes one finished Frame: frame start, descriptor/upload ring begin, Frame sort, per-view viewport/scissor/RT setup, clears and transitions, runs the draw executor, render-target resolve, statistics (timers via QPC, trace scopes), frame end. The RTX subclass overrides this slot with a wrapper that calls the base. Anchors: slot number 50 of the context vtable, size > 0x4000, 227 calls, many D3D12 COM thunks. [V order, I meanings]
- **Draw executor** [e821120]: walks the sorted index list; for each item loads the RenderDraw (0x540) and the draw header (0x80), counts executed items, picks branch A (resolve the program's shader variant through a hash map) or B (draw, including the ray-tracing/indirect path) from the state byte at header+0x23, builds/gets the PSO, binds descriptors and emits draws through the batcher. [V skeleton]
- **PSO builder** [e81e860]: decodes the 64-bit state and second state word into a pipeline-state description (write mask bits 0-3, depth function bits 4-7, four blend factors bits 12-27, blend equation bits 28-30), masks the key with 0x0707007FFFFFF0FF / 0xFFFFFF00FFFFFF00, builds input elements (semantic "TEXCOORD") and looks up / creates the PSO. [V partial]
- **Draw flush** [e81b720]: turns batched draw records (0x70 non-indexed, 0x88 indexed) into ID3D12GraphicsCommandList calls (DrawInstanced, DrawIndexedInstanced, ExecuteIndirect, barriers, vertex/index buffer binds, root constants). [V]

## RenderDragon frame graph and GraphicsTasks (render-prep thread)

- **BgfxFrameBuilder end-frame** [66232b0]: flushes deferred buffer then texture transactions, drains the GraphicsTasks queue, waits for the previous frame, creates the persistent UI colour/depth targets, applies the nine kinds of deferred resource transactions, handles the screenshot texture, sets up the frame-renderer modules, drains tasks and waits again, flushes the deferred transactions once more, and ends with the scope "FrameBuilder - End frame wait for render". Anchors: those strings. [V order]
- **Deferred transactions flush** [6632bf0]: processes the buffer job vector, then the texture job vector; each vector is converted to a job list, every job's virtual slot 1 is called, then each job is deleted through virtual slot 0. Anchors: strings "Deferred Buffer Transactions" and "Deferred Texture Transactions". [V]
- **Wait for previous frame** [c25f960]: joins up to two pending-frame futures and, when the mode word is 1 and the first future was set, runs GraphicsTasks Execute; then clears them. [V]
- **GraphicsTasks Execute** [c25fc50]: runs the task runner twice and then calls the bgfx frame() function once. Anchor: string "GraphicsTasks - Execute rendering tasks and frame". [V]
- **Task runner** [c25fe20]: pops queued std::function tasks into a local vector, runs them in FIFO order, destroys them. [V]
- **BgfxContext end-frame** [c270460]: encodes the frame graph (calls generate), runs the task dispatch, then walks the per-view objects, writes a present record, stamps timestamps and signals. Anchor: string "BgfxContext - Generate and encode frame graph". [V]
- **Frame-graph generate** [c273420]: consumes the Declarator's list of declared passes and builds per-pass resource-dependency records (24- and 40-byte elements), optionally orders passes by an explicit list of pass names, and stable-sorts the records. The sole caller passes an empty name list. [V partial]
- **Task dispatch** [e9002e0]: walks the 0x80-byte task entries (task object, shared control block, state, kind, id, live flag, debug colour), appends kind-1 tasks to the frame resources' task list and builds the run order; the task body is a std::function stored in the task object. [V]

## FrameBuilder inserts, visitors, extractors (L4/L5; facts from BGFX_MAP 6fu-6hj and docs/functions/group_visitors.md, re-read statically today only for the visitor prologues)

- **Group insert wrappers** [666aa00 effect, 6664760 UI, 6655de0 sky, 66466e0 item, 6640ae0 light, 6674050 editor]: six copies of one template: open a profiler zone named "FrameBuilder - Insert <group>" (TLS-guarded), call the group's visitor with the frame context and the variant, close the zone. Re-find: the zone strings are each referenced only by their wrapper; the wrapper's single non-profiler callee is the visitor. The wrappers are byte-identical except the string address, so a byte signature cannot tell them apart (only the Sky wrapper is unique). [V]
- **Group visitors** [66742f0 editor 8 cases, 666aca0 effect 9, 6664a00 UI 5, 66560f0 sky 11, 6646980 item 11, 6640d80 light 8]: a huge frame (0x3B10..0x9F91 bytes of code) that reads the variant tag byte at variant+8, switches through a jump table (cmp tag, N-1; lea table) and in each case either copies the description into a pass vector inside the frame context (queue, drained later by the pass), calls a dedicated extractor (item tags 3, 6, 8, 10) or draws directly (UI text). Re-find: the jump table size N-1 and the description sizes used as copy lengths. Layout constants of the visitors are asserted in layout_asserts.json. [V structure]
- **Thin insert clones** [21 functions, docs/functions/insert_thin_clones.md]: one template: copy the description into a shared_ptr'd render object (allocate, copy fields, push into the per-kind vector of the frame context), no other logic. Re-find: a short body that makes exactly one allocation and one vector push, with the description size as the copy length. [V]
- **Fat clones** [Nametag 1127330, PlayerVision 53e62b0, Shadow 53e6c30 (blob shadows through the mesh-fallback path), MeshFallback insert 4def480, Crack 539fff0, Clouds, SkinnedMesh]: build the draw items of one render object (mesh, material, uniforms) from the description in phases and submit them through the item writer. Re-find: by the description class name in the __FUNCSIG__ strings (insert<Render...Description>). [V/I]
- **Extractors** [ItemInHand 6698e30, BatchActor 66d9af0, Clouds 67375a0, Particle 67417f0, Weather 6745440, FlameBillboard, Gameface, Editor block volume]: read a description (rcx/r8 family) and build the draws or pass-vector entries for one object family; uniforms are named through FNV-1a 64 hashes of the uniform names (the extractor compares a static computed from the name). Re-find: the uniform name strings and hash constants (cbf29ce484222325 / 100000001b3). [V structure]
- **Shared helpers**: 0x5aba5c0 returns a thread-local object that queues pass vectors (not a pass lookup); 0x5679db0 writes one uniform value into a pass/draw uniform block; 0x675e440 is ResourceCache::get (keyed get-or-load, reloads stale keys, retire list); 0xbcbf730 + its job body is the async resource loader (pending jobs merged each frame by 0xc288990 from the end-frame, job runner processPending 0x6622610 -> 0x12893d0); 0xe86b730 loads a material (material.bin: header, AES-256-GCM encrypted body, per-stage shader pick, bgfx shader/program creation). [V structure]

## Pass declaration and execution (L6, VV frame graph)

- **Pass group builders**: each VV group builder declares its pass names and registers a std::function execute body; ScreenDraw passes share the declare 0xbbbd3d0 / build 0xbc37320 / execute body 0xbc04dc0 / submit 0xbcc38e0 path. Every group has an execute body of one of three shapes (docs/functions/pass_bodies.md); non-ScreenDraw bodies: deferred lighting, SSR (a ScreenDraw), TAAU (0xbc8cfd0 with RenderResolution/DisplayResolution uniforms), FSR1 (compute + fragment bodies), voxel upload, RTX denoise. Re-find: pass-name strings in the declaring function, uniform names inside the body. [V structure]
- **submitPass inline path**: writes the pass transform into the Frame matrix cache (setTransform) and calls Encoder::submit for each item. [V]

## M1d/M1e structural functions — behaviour notes without RVAs

One paragraph per structural function that has a D2 dossier; each is re-findable after a patch by behaviour (strings, constants, call shapes), not by address.

### FrameBuilder clones and visitors (L4)

- **Thin insert clones (21, one 0x139-byte template, docs/functions/insert_thin_clones.md):** each clone builds a `{desc*, u8 tag}` variant on its own stack, never reads the description fields, and forwards `{desc, tag}` through its group's `_insert` vtable slot (Editor/Effect/UI/Sky/Item/Light) via the CFG thunk `[0xF99FFA0]`. Re-find after a patch: the shared byte shape `mov [rbp+0x10],desc; mov byte [rbp+0x18],TAG; mov rax,[builder]; mov rax,[rax+slot]; lea rdx,[rbp+0x10]; mov rcx,builder; call [rip+thunk]`, occurring exactly 21 times, each a ~0x139-byte function whose tag byte and group slot differ per clone. [V shape]
- **Group insert wrappers (6):** one body per group (Editor 0x6674050, Effect 0x666aa00, UI 0x6664760, Sky 0x6655de0, Item 0x66466e0, Light 0x6640ae0). Each opens its TLS-guarded profiler zone "FrameBuilder - Insert <group>" (the zone string is unique per wrapper) then calls the group's visitor with `{builder, frameCtx, variant}`. Re-find: each zone string is referenced only by its wrapper; the wrapper's single non-profiler callee is the visitor. [V]
- **Group visitors (6, docs/functions/group_visitors.md):** each reads the variant tag byte at `variant+8`, switches through `cmp tag,N-1` + `lea jump-table`, and either copies the description into a pass vector inside the frame context (queued, drained later by the pass), calls a dedicated extractor (Item tags 3, 6, 8, 10 tail-jump to them), or draws directly (UI text). Re-find: the jump-table size N-1 and the per-group case entry addresses; the wrapper string disambiguates the group. [V structure]
- **Item visitor 0x6646980 (jump table 0xf2bf2d0, 11 tags, docs/functions/6646980.md):** the biggest visitor; switches on the Item variant tag and in each case either copies the description into a pass vector, calls a dedicated extractor (tags 3 ChunkGeometry, 6 ItemInHand, 8 BlockSelectionOverlay, 10 BatchActor), or draws directly. Tags 6/8/10 are bare tail jumps to their extractors. Re-find: `cmp eax,10` then `lea` into 0xf2bf2d0 (relative i32 targets). [V structure]

- **Fat clone PlayerVision [0x53e62b0] (Effect group, tag 3):** builds a 0x14-byte RenderPlayerVisionDescription on its own stack from the local player's state and inserts it through the builder's Effect-group vtable slot (+0x360) with tag byte 3. The description holds: night-vision/conduit-power presence (mob effect ids 16/26) with a fade scale (1.0 above 200 effect ticks, else 0.7 + 0.3·sin), the block light at the camera's floor block times 0.0625, a player float field, and a cosine-like pulse from the dimension counter (pi/40 argument). It reads only [rcx+8] of its argument (the player actor) plus a globally held frame-builder reference (acquire/release pair around the renderer's globals), and returns early when the builder is null or inactive. Re-find after a patch: the FrameBuilder - Insert profiler string at function start, constants 0.0625 / pi/40 / 0.2 / 0.3 / 0.7 / 200, the tag-3 byte store before the +0x360 vcall, and the loop stepping by 0x60 over effect instances. [V for the stores, the +0x360 tag-vcall shape and the constants; I for the effect-id names (matched to the vanilla night-vision formula) and the player-field name.]

- **Fat clone Shadow [0x53e6c30] (blob shadows through MeshFallback):** emits one queued entry per shadow: pushes a copy of the matrix stack's top 4x4 (push [0x53d0be0]), translates by minus camera position then by the entry position, applies uniform scale, draws the entry mesh twice through MeshFallback insert [0x4def480] with materials from state +0x638/+0x640, then draws one more mesh (mesh +0x618, material +0x648) after the loop and writes a vec4 parameter into the extraction context at +0x30. Reads extraction context at [rcx+0x8/+0x10] and shadow state at [rcx+0x10] (+0x0C/+0x14 camera, +0x5F0/+0x5F8 entry vector, +0x608/+0x618 meshes, +0x650 vec4 params). Re-find: three 4-entry jump tables at 0xf24a198/0xf24a1a8/0xf24a1b8, calls to MeshFallback insert [0x4def480], matrix push [0x53d0be0]. [V for offsets/calls; I for blob-shadow role name.]

- **Fat clone MeshFallback insert [0x4def480] (Item group, tag 2):** generic mesh insert: renders one mesh with one material and its texture bindings. Rejects when shouldRender [0x4def080] is false, when the material pointer or its +0x40 is null, or when no frame builder exists. Resolves each 0x28-byte binding (4 kinds via jump table) into a {resource, control-block} pair with an extra strong reference, copies the newest 0x40-byte camera record from the context ring, builds the params variant, then builds a RenderMeshFallbackDescription via ctor [0x668b850] and inserts it into the Item group (vtable slot +0x378, tag byte 2), releasing every temporary on the cleanup path. Re-find: FrameBuilder - Insert string, ctor call [0x668b850], tag-2 byte store before the +0x378 vcall, 0x28-stride binding loop. [V for calls/offsets/tag; I for generic-mesh role.]

- **MeshFallback description ctor [0x668b850] (RenderMeshFallbackDescription, 0x1D0 bytes):** copies the 16-float camera matrix, vec3 camera position, five flag bytes, two 16-byte memcpy blocks from context pointers, the material shared_ptr (+1 strong ref on its control block), a params pointer plus six material parameter values (vec4/vec2/float), an optional vec4 override (has-flag at +0x10), flags u16, a 16-byte variant head copy with variant byte/index (4-kind jump table 0xf2bf660; index 1 allocates a 0x20-byte payload block via allocator 0x9bc830), six bound floats and the mesh's vec4, then converts each 16-byte texture binding via [0x4dfb570] into the texture array (extra strong refs kept). Re-find: 4-entry jump table 0xf2bf660, call [0x4dfb570], allocator call 0x9bc830. [V for every store (instruction-complete, D2); I for field names.]

- **Fat clone Crack [0x539fff0] (Item group, tag 5):** three phases: with no active frame builder it draws each crack entry as a generic mesh via [0x4defed0] using the two crack materials; otherwise it builds one RenderCrackDescription per entry (mesh, crack texture shared_ref via [0x4dfb570], newest camera-record pointer, entry stage, flags from context byte +0x74) and inserts it into Item as tag 5 (vtable slot +0x378) inside a FrameBuilder - Insert profiler zone; finally it walks the LevelRenderer intrusive destroy-progress list (+0xEC8) and rebuilds the crack mesh of every breaking block (position +0x10, progress +0x20, region +0x978) via [0x6a5e8f0]. Re-find: tag-5 byte store before the +0x378 vcall, the destroy-list walk, texture convert [0x4dfb570]. [V for phase 2; phases 1/3 structure only [I].]

- **Shared fat text clone [0xe71330] (EnvironmentalText Item tag 0 via +0x378 / UIText UI tag 3 via +0x368):** takes a source pointer, font texture, 16-float matrix, position vec3, text shared_ptr and optional parameter block; increments the font/texture reference (lock inc [rcx+8]) and dispatches to the EnvironmentalText ctor [0x668b400] or the UIText ctor [0x668c750] depending on the group. Re-find: the two FrameBuilder - Insert strings, the tag-0/tag-3 byte stores before the +0x378/+0x368 vcalls. [V for the ref-count increment and ctor calls; group/tag mapping [V] per docs/functions/6w.md.]

- **EnvironmentalText description ctor [0x668b400] (RenderEnvironmentalTextDescription, 0xE8 bytes):** source pointer, converted font texture ([0x4dfb570]), 16-float matrix, vec3 position, 16-byte block memcpy, text shared_ptr (+1), two flag bytes at +0x88/+0x89, six material parameter values (each read at param+0x40: vec4/vec2/vec4 then vec4/vec2/float), optional vec4 override (has-flag), flags u16. [V, instruction-complete D2.]

- **UIText description ctor [0x668c750] (RenderUITextDescription, 0x60 bytes):** source pointer, fields at +0x08/+0x20/+0x28/+0x30, converted font texture ([0x4dfb570]), flags u16 at +0x38, flag byte at +0x3A, variant index initialized 0xFF then set from the variant's index after a 4-kind jump-table payload copy (0xf2bf690; index 1 allocates a 0x20-byte block via allocator 0x9bc830). [V, instruction-complete D2.]

- **BlockSelectionOverlay clone [0x539b7c0] + ctor [0x668d990] (Item group, tag 8):** clone builds the 0xB8-byte RenderBlockSelectionOverlayBlockEntityDescription: 16-float matrix, mesh pointer, u32 value at +0x30, 16-byte block memcpy, texture (optional convert via [0x4dfb570] when non-null), material shared_ptr (+1), color vec4 memcpy, flags u16, and a 3-kind variant payload (index at +0xB0, 0xFF = empty). The clone reads the selected-block context (+0x28/+0xB0), resolves the block entity via [0x3853770], writes tag byte 8 before the Item-group vtable dispatch (+0x378) inside a profiler zone, and dispatches through the CFG thunk call [0xF99FFA0]. Re-find: tag-8 store right before the +0x378 vcall, CFG-thunk dispatch [0xF99FFA0], ctor call [0x668d990]. [V for ctor stores; tag store location [V] per dossier; clone-level role [I].]

- **Sky clone [0x5369b30] + Sky ctor [0x668c910]:** Sky clone builds cubemap/sky/end-sky related descriptions — calls the cubemap description producer [0x6606580], EndSky thin clone [0x53707a0], CelestialBody [0x5370b20] and LightDirectional [0x5370960] thin clones, Sky ctor [0x668c910], a pure mat4 multiply [0xaa6580], and MeshFallback inserts [0x4def480] x2. Sky ctor builds the 0xB0-byte RenderSkyDescription: source pointer, sky texture (convert via [0x4dfb570] with a static default texture when null, +1 strong ref), flags u16, 16-float color memcpy, 16-float matrix memcpy, a 6-float UV transform expanded to a 4x4, and a scalar value. Note: per the ctor's dossier this Sky description is consumed by EndSky (Sky tag 3, thin clone [0x53707a0]); tag 5 (Sky/Stars) builds an inline RenderSkyColorsDescription at 0x536a2e3 — the clone body itself is not instruction-decoded [I]. Re-find: cubemap producer call [0x6606580], ctor call [0x668c910], mat4 multiply [0xaa6580]. [V for ctor and call sites; clone body [I].]

- **Shared helpers:** 0x4def080 shouldRender gate used by Nametag/MeshFallback/Crack; 0x4dfb570 texture convert called by every description ctor; 0x5aba5c0 returns a thread-local object that queues pass vectors (not a pass lookup). Re-find: the shouldRender early-return pattern, the single 0x4dfb570 call in each ctor, the 0x5aba5c0 call returning a TLS object. [V for call sites; roles [I].]

### Extractors (L5)

- **ItemInHand extractor 0x6698e30 (docs/functions/item_in_hand_ctor_path.md):** reads an ItemInHand description and builds the draw items of one held-item render object: validates the description, gathers the transform packet, copies the AABB and material fields, then submits the build through the item writer. Re-find: the desc.d78 flag-bit test selecting the Textured variant, the movsd/movss copies of desc+0x6C/desc+0x68, and the call chain into the item writer. [V structure]
- **BatchActor extractor 0x66d9af0 (docs/functions/66d9af0_builders.md):** reads the whole-frame actor batch description (instance array, stride 0x48, each instance holds model geometry + transform), keeps a sorted actor-id list (binary search + insert), binds per-draw material parameters by name hash (TintedAlphaTestEnabled, MetalnessUniform, EmissiveUniform, ... PrevBones, MERSTexture, ...), then calls the ten variant draw-list builders (0x66BB7B0 .. 0x66C98E0). Re-find: the 18 uniform-name .rdata strings and the XXH64 helper 0x19932c0 used ~30× to hash material/variant keys. [V structure]
- **Chunk geometry extractor 0x66ea3d0:** reads a ChunkGeometry description and emits the terrain/chunk draws (RenderChunk, WaterPrepass, EndPortal paths) through its body builders A-D and bodyActor. Re-find: the extractor strings and material/uniform anchors in docs/functions/66ea3d0_bodies.md. [V structure]
- **Skinned-mesh extractor (producer 0x4e39f20 + builder 0x668d350):** builds a RenderSkinnedMeshDescription from the skinned description via two 0x1A8 intermediates; the general insert clone 0x6b84e60 tail-builds it. Re-find: the builder store table for every RenderSkinnedMeshDescription field and tag-7 store. [V]
- **Nametag extractor (producer 0x11276b0):** the Nametag fat clone 0x1127330 builds the 0x98-byte description from per-frame camera/transform records then dispatches tag 1 through the Item visitor; there is no separate extractor RVA — the visitor case builds it inline via ctor 0x668b6e0 and 0x668b6e0 builds it in place. [V structure]
- **Clouds extractor 0x67375a0 / constructor 0x668e940:** builds Clouds description from its fields (mat4 block, vec3 camera, shared_ptr, vec4 optional) and queues it; structure reversed, full field decode not yet closed. [V structure, I field meanings]
- **Particle extractor 0x67417f0:** ParticleForwardPBR/ParticlePrepass/Particle draws; structure reversed, inner field decode not yet closed. [V structure]
- **Weather extractor 0x6745440:** WeatherForwardPBR/Weather/NoVariety/PointLightShading draws; head reversed only. [V structure]

### Pass lambdas / frame-graph bodies (L6)

- **DoDeferredLighting 0xbc2c590 / DirectionalLightingPass 0xbc2cd20:** deferred-lighting pass object (vtable slot 2 = execute). Sets the view rect and four matrices from `this` (+0x88 rect, +0x08/+0x48/+0x9C/+0xDC mat4, +0x11C 16B, +0x98 sort byte) into s_ctx's per-view record, opens a scope, binds the material (findPass by FNV-1 hash of the pass name, e.g. DirectionalLightingPass 0x993692FCF6FC1544), applies state, binds vertex/index streams, sets the 0x58-byte stencil/blend block from `r+0x23C`, and submits via submitPass. Out: the view's framebuffer (light accumulation target). [V body, I out]
- **DoDeferredShading 0xbc2d550 / 0xbc2dd20:** same deferred template shape, different pass hash. [V structure, I]
- **WaterExtinction 0xbc2eb50 / WaterSurface 0xbc2f4a0:** same deferred template shape; WaterSurface also does material +0x23C/+0x294 state selection and geometry loads at +0x1A0/+0x23C. [V structure]
- **VoxelCombine 0xbc0b240 (Combine):** compute pass; sets view state from `this`, binds material by holder, writes the DirtyVolumeCount uniform (static hash slot 0x12adf6d0-8, value `(float)DirtyVolumeCount` splatted to vec4) via setUniform 0x5679db0, binds material/state, finds the "Combine" pass by hash 0x04e50856c4371e38, program 0xbcc7ce0, and dispatches via EncoderImpl::dispatch 0xbc61140 (numY = DirtyVolumeCount). In: voxel buffers from the scope binding vector; out: VoxelBuffer. [V body, I out]
- **ClusterLights 0xbc5bad0:** compute pass; sets view state, six uniforms by name hash (LightsPerCluster, ClusterNearFarWidthHeight, CameraFarPlane, AngularRefinement ...), three dynamic-buffer updates via 0xbc70ff0 (zLights, Extends, zLightLookupArray), builds the pass name on the stack ("Cluster"+"Lights", hash 0xaa53f452a8d4b31a, lookup 0xc4bba0), variant selection via "AngularRefinement"/"Off", submits via compute dispatch 0xbc61140. In: light arrays from Resources; out: the three cluster buffers. [V structure]
- **ScreenDraw shared body 0xbc04dc0:** the execute body of every ScreenDraw std::function pass (ColorPostProcess, forward, NothingTask group, bloom, local exposure, ...).
