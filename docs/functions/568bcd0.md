# Dossier: common pass task, encode step (0x568b9e0) and render-thread body (0x568bcd0)

1.26.62.01. Both fully reversed (0x568bcd0: all 55 instructions; 0x568b9e0: the tail that matters, its head is a shared_ptr release). Tags: [V] read from disassembly.

## Purpose

The frame-graph pass tasks of the common class (vtable 0xF25C7B0, the 14 "Scene"-type tasks of a world frame) do their GPU work in two steps:
1. **encode (0x568b9e0, a virtual of the task class; prep thread):** queues one custom item on the pass's view: `encoder->submitCustom(viewId, &renderThreadBody, this)` (tail jump to 0xbc61560).
2. **renderThreadBody (0x568bcd0, static; render thread):** called by the D3D12 executor for that item (key bit 53, BGFX_MAP 6fg) as `fn(user, ctx)`; it invokes the task's stored `std::function` (the pass body at task +0x70) with the executor context published through the view reference.

## What this changes

- The pass body (`std::function` at task +0x70) runs **on the render thread, inside the D3D12 executor, in sort order within its view**, and reaches the command list through `view->execCtx`. Disabling a pass by swapping the functor (TaskDispatchHook) still works because the functor is only read here.
- Sibling classes use the same pattern with different offsets for the view reference: 0x5699be0 (+0xB0, body 0x5699e30), 0x56c85c0 (+0x108, body 0x56c8810), 0xbc04270 (+0x3B0, body 0xbc04530); 0x56ca2f0 and 0x56d0d60 are two more tail jumps not read yet [?].

## All pass classes share this body (diff of the four bodies, 62.01) [V]

The render-thread bodies 0x568bcd0, 0x5699e30, 0x56c8810 and 0xbc04530 are the same 55 instructions; only three displacements differ (the argument word, the ViewRef pointer and its control block). The task classes are instantiations of one template whose tail is `{ std::string name (0x20 bytes); void* arg0; std::shared_ptr<ViewRef> view; }` after a per-class payload, with the functor always at +0x70 / +0x78:

| encode | render-thread body | name at | arg0 | ViewRef* | control block |
|---|---|---|---|---|---|
| 0x568b9e0 | 0x568bcd0 | +0x2C0 | +0x2E0 | +0x2E8 | +0x2F0 |
| 0x5699be0 | 0x5699e30 | +0x88 | +0xA8 | +0xB0 | +0xB8 |
| 0x56c85c0 | 0x56c8810 | +0xE0 [I] | +0x100 | +0x108 | +0x110 |
| 0xbc04270 | 0xbc04530 | +0x388 [I] | +0x3A8 | +0x3B0 | +0x3B8 |
| 0x56ca2f0 (tail jump) | 0x56ca4c0 (lea target) | not read | | | |
| 0x56d0d60 (tail jump) | not read | | | | |

The "name at" column for the first two rows matches the offsets already in Tasks.h (kCommonPassName 0x2C0, kClearWrapperName 0x88), which confirms the tail layout: arg0 sits right after the 0x20-byte name. For the other rows the name offset is derived by that rule, not read.
