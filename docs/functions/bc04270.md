## Ownership / threading

The strong/weak counts use locked RMW (lock inc/lock dec), i.e. full barrier semantics [V].
The destructor/deleter calls run the object's vtable slots with RCX = old object; the
deleter may free the object. No other shared state is touched. Footprint (static):
a0+0x3A8..0x3C0 (the three fields written) [V]; writes to the ref-counted object's
strong/weak counts go through run-time pointers (a1+0x10, old a0+0x3B8) and are outside
the static footprint - a V2 differential run can neither compare nor undo them, so the
thread-model proof plus V3 whole-frame coverage applies to those effects (spec section 8).
