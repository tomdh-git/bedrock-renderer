Confirmed by all 4 callers (each does `movsx rcx,byte ptr [...]; inc rcx; mov rdx,<ptr>; mov r8,<ptr>; call 0x4E01C30`) and by the prologue consuming RCX as the table index and using R8 for [r8+8]/[r8+0x18]. ## Register/argument map

- RCX/index: consumed at 0x4e01c3d (`movsxd rcx,[rax+rcx*4]`); also reloaded as `this` (RCX = rsi) before every thunk call.
- RDX/a1: never read; forwarded in RDX on computed tail jumps (jmp rcx leaves RDX unchanged).
- R8/a2: handle; [r8+8] and [r8+0x18] read as object pointers. R8 is saved/restored around calls (R8 is volatile, clobbered by calls: `mov rdi,r8` / `mov r8,rdi`).
- RSI: object pointer (this), callee-saved, pushed/popped.
- RDI: callee-saved scratch for R8 save/restore, pushed/popped.
- RAX: scratch (vtable loads, target address).
- No stack arguments read; no stack writes except the prologue/epilogue frame.
