## OPEN questions

- The free list array manipulation at 0xbc730c1-0xbc730cc is unclear: it writes `r8w` (the old freeCount) to `freeArr[handle*2]`. This may be maintaining a reverse mapping.
- The logger writes appear to write a fixed-format record: tag(1), pad1, handle(2), shader(2), 0xFFFF(2). The alignment logic (and ecx, 0xFFFFFFFE; add 2) suggests 2-byte alignment.
- The second destroy call at 0xbc7327a jumps back to 0xbc73187 if bl is set - this appears to be a double-destroy for some cases.
