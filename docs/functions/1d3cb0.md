struct StringPair {
    // First string (offset 0x00)
    char*       ptr0;        // +0x00: heap pointer (when not SSO)
    uint64_t    size0;       // +0x08: current length
    uint64_t    capacity0;   // +0x10: capacity (or 0xF for SSO)
    // Gap 0x18..0x1F? Actually +0x18 is used for capacity in first string
    // Wait: [rsi+0x18] is read as capacity0 at 0x1d3cdc
    // [rsi+0x10] is written as size0 at 0x1d3d0f
    // [rsi+0x00] is read as ptr0 at 0x1d3d0c
    // So layout at +0x0: ptr, +0x8: size, +0x10: capacity? But [rsi+0x10] is written with rdi (size)
    // Let me re-check:
    // 0x1d3ccb mov rdi,[rdx+0x10]  -> src size at +0x10
    // 0x1d3ccf cmp qword ptr [rdx+0x18],0x10 -> src capacity at +0x18
    // 0x1d3cdc mov rax,[rsi+0x18] -> this capacity at +0x18
    // 0x1d3d0f mov [rsi+0x10],rdi -> this size at +0x10
    // 0x1d3d0c mov rbx,[rsi] -> this ptr at +0x0
    // So for String (single): +0x0=ptr, +0x8=?, +0x10=size, +0x18=capacity
    // But standard std::string is typically: ptr, size, capacity (24 bytes)
    // Here +0x8 is not directly accessed. Maybe +0x8 is unused or SSO buffer.
    
    // Second string (offset 0x20)
    char*       ptr1;        // +0x20: heap pointer (when not SSO) or SSO buffer
    uint64_t    size1;       // +0x28: current length (not directly seen, but [rsi+0x30] is written)
    uint64_t    capacity1;   // +0x30: written at 0x1d3d6b, read at 0x1d3d41
    // Wait: 0x1d3d28 mov rdi,[r14+0x30] -> src size1 at +0x30
    // 0x1d3d2c cmp qword ptr [r14+0x38],0x10 -> src capacity1 at +0x38
    // 0x1d3d41 mov rax,[rsi+0x38] -> this capacity1 at +0x38
    // 0x1d3d6b mov [rsi+0x30],rdi -> this size1 at +0x30
    // 0x1d3d67 mov rbx,[rsi+0x20] -> this ptr1 at +0x20
    // 0x1d3d3d lea rbx,[rsi+0x20] -> SSO buffer address at +0x20
    
    // Flag at +0x40
    uint8_t     initialized; // +0x40: 0=uninitialized, 1=initialized
    // Total size at least 0x41

Actually, looking more carefully at the first string accesses:
- `src` (rdx): size at +0x10, capacity at +0x18, data ptr at +0x0 (when not SSO)
- `this` (rsi): capacity at +0x18, size at +0x10, data ptr at +0x0 (when not SSO)

So the String layout appears to be:
- +0x00: data pointer (heap) or SSO buffer start
- +0x08: ? (not directly accessed)
- +0x10: size
- +0x18: capacity

This matches a 32-byte string with SSO buffer at +0x00..+0x0F (16 bytes), then size at +0x10, capacity at +0x18. The +0x08 might be part of SSO buffer or a separate field.

For the second string at +0x20:
- +0x20: data pointer or SSO buffer
- +0x28: ? (not directly accessed)
- +0x30: size
- +0x38: capacity

And +0x40: initialized flag.
