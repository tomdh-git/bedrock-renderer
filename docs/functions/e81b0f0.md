## Register / argument map

- rcx / rsi = `self` (RendererContextD3D12*). `mov rsi,rcx` at 0xe81b0f8.
- rax: scratch / vtable target / loop countdown.
- rdx: cleared to 0 for the first virtual call (0xe81b117), then the loop counter
  0..count (0xe81b13a / 0xe81b184); passed as arg2 of the second virtual call.
- r8: current element pointer (0xe81b18d), then advanced to its `next` (0xe81b178).
- r9: ring slot index, then reused as the loop-counter copy for the stack store.
- rcx (reused): `&this->[0x3C55B10]` (ring tail cell) during the loop (0xe81b133),
  then `this->[0xCC9268]` for the second virtual call (0xe81b1e6).
- xmm0: zero, used by `movups` to clear tail+head (0xe81b13c / 0xe81b150).

## Structure

1. /GS prologue (0xe81b0f0..0xe81b105): save rsi, allocate 0x8B0 of stack, store the
   stack cookie `(__security_cookie ^ rsp)` at [rsp+0x8A8].
2. Guarded virtual call `self->vtable[0x1E8](self, 0)` (0xe81b10d..0xe81b119).
3. If `self->[0x3C55288]` (pending count) is non-zero, run the flush loop
   (0xe81b12f..0xe81b18b), then the guarded virtual call
   `self->[0xCC9268]->vtable[0x50](obj, count, &nextPtrs)` (0xe81b1e6..0xe81b1f9),
   then clear the pending count to 0 (0xe81b1ff).
4. /GS epilogue (0xe81b20a..0xe81b229); cookie-mismatch cold path
   (0xe81b22a..0xe81b23a) calls sub_e951550 and int3.
