## Ownership / threading

Refcount updates are `lock dec` (full barrier, seq_cst), so the function is safe to call from any thread provided the handle and the pointed-to objects are valid for the duration of the call — the same contract as the exe. The virtual methods invoked through the thunk run synchronously and may release/free the object; nothing is called after the object's lifetime ends except the refcount decrements that guard them. No heap allocation, no locks besides the refcount atomics, no SEH, no null guards beyond the explicit `test/jz` branches in the original. Fail fast (no added null guards).
